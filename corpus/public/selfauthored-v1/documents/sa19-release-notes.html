Lumenrake 4.2 release notes

4.2.0 · minor release · supported until 4.4

Highlights

  • A shared remote cache, so that a result built once on the CI server can be reused on every laptop.
  • Structured logs with --log-format json, one event per line.
  • The planner now skips packages whose inputs have not changed, which makes an unchanged run finish in under a second on most repositories.
  • Lint baselines: record today’s findings once and see only new ones afterwards.

Upgrading from 4.1

Most projects can upgrade by changing the version in their tool manifest. Two changes need attention. First, the settings key cache_dir has been renamed to cache.directory; the old name still works but prints a warning. Second, the default log format on CI systems is now "github" rather than "text", which groups the output of each task into a collapsible section.

If you pinned the old behaviour in a wrapper script - for example to keep log files parseable - add the flag explicitly. The migration guide on the documentation site walks through both changes with examples, and the local copy of the guide ships inside the release archive.

[cache]
directory = ".lumenrake/cache"
remote = "https://cache.example.org/lumenrake"
read_only = false

[log]
format = "json"
level = 'info'

The remote cache needs a server that implements a simple HTTP interface for storing and retrieving blobs. Any object store behind a small proxy will do; the documentation lists two tested setups.

Fixed issues

  • The scheduler no longer starts a task twice when two of its inputs change within the same second.
  • Paths containing spaces are quoted correctly in the generated shell scripts.
  • The --since flag now follows renames instead of treating a moved file as deleted and added.
  • Ctrl-C during a remote cache upload no longer leaves a partial entry behind.
