# Source-bound findings and consumer integration

The package root is the supported JavaScript entry point. Node 22.13 or later can use ESM or
`require("breaklint")`; TypeScript declarations ship with the same package. Private source imports
are deliberately not exported. Document renderer peers remain optional for screen-only consumers.

## Separate contracts

| Contract | Version | Boundary |
|---|---:|---|
| Document report | 4 | Findings, positive/declined evaluations, artifact/source/evidence identity |
| Measured snapshot | 4 | Internal geometry input with source/evaluation prerequisites |
| Configuration | 1 | Existing generated `breaklint/config.schema.json` |
| Producer record | `studio-producer-record-v1` | Host-launched producer, FD 3, captured bytes |
| Declared source manifest | 1 | Matching-byte declaration; never producer authority |
| Screen report | 1 | `profileKind: "screen"`, route/viewport/scenario geometry |
| Screen options | 1 | Closed runtime validation and exported `SCREEN_OPTIONS_SCHEMA` |
| AI context / comparison | 1 each | Bounded projection / explicit continuity decisions |

Report 3 consumers must migrate when adopting 0.5.0. A legacy report can be displayed as legacy;
it cannot acquire original-source or repaired-target claims. The old scalar finding measurement
remains, while `evaluations[].measurements` and `predicate` preserve compound rule decisions.

`runFindingId` is local to a run. `stableIdentity` explicitly states unique, ambiguous or unavailable.
A selector or generated source line is not a source map. Page-only and generated targets can have
useful measurements while their editable original remains unknown.

## Producer boundary

`checkProducedDocuments({ producer, options })` launches only the executable and arguments selected
by host code. Its `producer` carries `trust: "host-controlled-producer"`, `id`, `executable`, `argv`,
`codeFiles: [{id, path}]` and `producerOptions`. None of these may be taken from untrusted document
text. The API adds a unique run root/ID, captures registered code before/after and waits for the
producer process group to finish. A partial output, missing expected input, extra receipt data,
hash mismatch or unsuccessful process cannot silently reuse a previous run.

The producer writes one bounded UTF-8 JSON record to FD 3 and closes it. The record contains:

- `protocol`, current `runId`, matching `producerId`, and `complete: true`;
- complete `expected` and actual `reads`, each `{path, sha256, bytes, role}` where role is authoring,
  dependency or asset;
- `outputs`, each `{path, sha256, bytes, pieces}`;
- exact options and code inventory `{sha256, files, dependencies}`.

### Producer option validation

`checkProducedDocuments` validates a closed runtime invocation before it resolves configuration or
creates a producer process. The top-level input, `producer`, every `codeFiles` row, `options`,
`network`, and optional Git `revision` admit only their documented fields. `network.mode` is
`"offline"` with an empty allowlist or `"allowlist"` with a non-empty one; booleans remain
booleans. This prevents an unknown option or network mode from being ignored and prevents malformed
calls from starting a custom executable.

Malformed invocation shape or value type is programmer misuse and rejects with `TypeError`, before
any process starts. A well-shaped invocation whose configuration is semantically invalid still uses
the existing typed `{ ok: false, code, detail }` result, also before process creation. Receipt,
renderer, and acquisition failures use that same typed result; the public success/result shape does
not expose a capability or captured source bytes.

An imported manifest remains declarative. Its producer `id` and dependency digest inventory must
match the current FD3 record; the manifest's `producer.version` remains declared metadata because
the v1 host protocol has no host-bound producer-version field. The current host-controlled receipt
requires an empty dependency inventory, so a syntactically valid declared dependency cannot turn
into producer authority.

Captured blobs are stored by SHA-256 under the host-provided `blobs/` directory. A copy piece uses
`{kind:"copy", inputPath, inputStart, inputEnd, outputStart, outputEnd}` with half-open byte ranges.
A generated piece uses `{kind:"generated", outputStart, outputEnd}`. Copy edges are checked against
the captured bytes, including intermediate artifacts; generated bytes acquire no automatic original
source. Records are limited to 10 MiB, 2,000 inputs and 256 MiB captured content. Safe relative paths,
regular-file capture and symlink rejection apply before source data is consumed.

This verifies a host-controlled build, not a dishonest producer or compromised host. A separately
provided `DataSourceManifest` can verify a copy predicate but remains **declared**. An opaque
in-process producer capability is not serializable or reproducible by setting a JSON flag.

Finding source coordinates name `utf8-bytes-unicode-codepoints-v1`: offsets are half-open UTF-8
bytes; line/column presentation counts decoded Unicode code points. `finding.source` addresses the
captured input artifact. `originalSource.location` addresses the verified editable leaf only when
the copy chain and inventory prove it. The location includes a role, digest and byte count; unknown
and duplicate origins remain visible.

## Digital Product Studio

The first real consumer preserves source pieces in its existing generator and print-edition path,
before chapter/block provenance is lost. Its host project register selects a fixed adapter; it does
not infer executable commands from a manifest. The Python advisory entry point invokes the installed
public package through a fixed Node bridge:

```bash
python3 _tools/breaklint_layout_report.py <product-directory> \
  --breaklint <consumer>/node_modules/breaklint \
  --out-dir <private-report-directory> \
  --output-path build/13-what-a-red-light-is-worth.html
```

Repeated `--output-path` selects existing multi-file inputs. Expected outputs are checked; this is
not a second batch implementation. A fresh attempt is published before child startup. `current.json`
can point only to that attempt; older successful reports remain historical. The Python wrapper stays
advisory (exit 0) while retaining the actual checker exit 0–4 and explicit unavailable state.

The bridge adds optional bounded ZIP delivery binding, then calls `writeReportBundle` on the final
canonical report. Archive inspection captures bytes once and validates member headers, names, CRC,
actual decompression limits and the complete mapping without extracting files. `local-package-bound`
means matching local package bytes. `delivery-verified` additionally requires matching current seller
attachment readback. Covered and omitted members remain listed; it is not a purchase or download
receipt. Private product bytes and seller metadata are kept outside this public package.

The retained `diagnostic-pdf` is the exact selected PDF from the measured acquisition. Its hash binds
the checked input; its `delivery: "not-asserted"` prevents a separate native PDF from borrowing page
addresses. The Studio native print renderer remains a different artifact. A green diagnostic render
does not establish the shipped native PDF's layout.

## Existing Playwright page and DS_OS

`checkPage` observes a caller-owned, already prepared page. It does not navigate, authenticate,
resize, scroll, change network policy or close it. Pass route state through the actual page and name
the scenario; the adapter records current route, viewport, browser and screenshot identity.
`trust: "host-controlled-page"` and `networkPolicy: "host-owned"` explicitly retain the caller's
authority. Document text cannot authorize new network access.

The `web-geometry-v1` semantics cover unexpected horizontal overflow and content cut by rectangular
clipping ancestors. Named allowed scroll containers and intentional overlays retain reasons and match
counts. Hidden/off-viewport nodes are exclusions, not positive repairs; inert/ARIA alone do not hide
geometry. Non-axis-aligned transforms, unsupported paint, opacity other than 1, active animations,
capture drift, font timeout and truncated inventory prevent a clean claim.

DS_OS reuses its existing authenticated E2E navigation, scenario fixtures and five viewports. The
shared overflow harness adds canonical breaklint diagnostics while retaining its independent width
assertion. A dedicated scenario suite and reporter enumerate expected states before navigation and
retain missing/skipped/aborted attempts and retry inconsistencies. This is hermetic frontend evidence,
not a backend correctness, live operational-state or human usability claim.

Its production build records sorted source/config/lock file hashes. A generated build ID is compiled
into `<meta name="breaklint-build">`; sources are checked again after `next build`. Completed builds
record the compiled output inventory as a separate receipt. The fixed `host-build-container` adapter
requires both `receiptPath` and `buildOutputReceiptPath`, and verifies current source bytes,
compiled output bytes and the page ID before/after capture. Preparing a build invalidates previous
receipts; only a successful, unchanged build creates completed receipts. Symlinked sources, receipt
paths and build outputs cannot obtain a verified binding.
The result is `verified-container-only`, method `build-bound-component-container`, for the named
component file. Editing source while an older build runs invalidates that association. JSX line
positions and component causes are not inferred.

## Evidence, repair and limits

`writeReportBundle(report, {outDir, evidenceDir})` writes canonical JSON, bounded untrusted AI context
and an offline HTML view. Current PNG/PDF bytes must match the report before links are emitted. A
crop/outline uses the same verified full-surface asset and names its coordinate system. Corrupt or
missing evidence remains visibly unavailable. The view neither runs scripts nor loads remote assets.

`compareReports(before, after, {revision:{repositoryRoot}})` returns new, persisting, resolved,
unmatchable and not-sufficiently-measured. Resolution needs the same provable logical target and a
positive compatible measurement of all parts, not merely no new finding. Actual Git ancestry is
checked for different commits; matching opaque revision labels are insufficient. See
[revision comparison](revision-comparison.md) for the closed identity and embedded-font boundary.

System/fallback font identity cannot currently prove a repair. Public-corpus renderer failures remain
explicit infrastructure/nonmeasurement, and rules remain uncalibrated. Additional chapters of the
same template do not establish independent corpus breadth. A short agent exercise does not measure
human time savings or a two-week field effect. No accepted-findings suppression, automatic repair,
universal crawler, native PDF source reconstruction or external trust-root service is introduced.
